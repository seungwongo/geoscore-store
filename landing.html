왜 GEO인가

검색의 규칙이 바뀌었습니다

사용자는 링크 10개 대신 합성된 답 하나를 받습니다. 그 답은 두세 개에서 일고여덟 개 도메인만 출처로 인용하죠. 상위 10위에 드는 것과, 그 좁은 인용 자리에 드는 것은 다른 게임입니다. 기존 SEO 도구는 키워드·백링크를 보지만, AI가 인용을 결정하는 축은 보지 않습니다. GeoScore는 바로 그 축을 채점합니다.

기능

진단으로 끝내지 않습니다

점수 → 근거 → 고칠 문장까지. 콘텐츠 담당자·마케터·1인 사업자를 위한 실전 도구.

📊

GEO Readiness Score & 스코어카드

0~100 종합 점수와 판정 라벨을 한눈에. 항목별 가중치 막대와 인용될·안 될 이유 Top 3까지 정리합니다.

  • 라벨: 인용 준비됨 · 인용 후보 · 보강 필요 · 인용 어려움
  • 콘텐츠 소점수 × 0.7 + 기술 소점수 × 0.3
  • 미채점 항목은 분모에서 제외해 비례 환산
🧩

하이브리드 채점 (키 없이도 동작)

콘텐츠 10개 + 기술 5개 항목을 채점합니다. 로컬 휴리스틱(정규식·DOM 분석)으로 API 키 없이도 11개 항목이 즉시 나옵니다.

  • 휴리스틱: 통계 밀도·출처·인용구·질문 커버리지·최신성·저자 권위 + 기술 5개
  • BYOK: 본인 LLM 키를 넣으면 정성 항목 4개 + 문장 재작성이 채워짐
  • 오프라인·API 오류에도 리포트는 항상 완성
✍️

CEP(상황 진입점) 맥락 진단

사용자가 AI에 실제로 던질 상황(누가·언제·왜·경험·제약·기준)을 이 페이지 기준으로 6~8개 도출하고, 각 상황 대응도를 평가합니다.

  • 대응도: 충분 · 부분 · 미대응
  • '제품 중심 → 상황 중심' Before → After 문장 재작성
  • 각 상황에 필요한 검증 가능한 근거(수치·출처) 안내
🛠️

기술 진단 & 복붙 처방

AI 크롤러 차단(robots.txt)·SSR 렌더링·구조화 데이터(JSON-LD)·llms.txt를 점검하고, 바로 붙여넣을 스니펫을 만들어 줍니다.

  • GPTBot·ClaudeBot·PerplexityBot 등 7종 크롤러 접근성 판정
  • robots · JSON-LD · llms.txt 처방 스니펫
  • 복붙용 '인용 준비된 도입부 블록'
📤

리포트 출력 & 히스토리

진단 리포트를 마크다운·HTML·DOCX로 내보내고, 최근 진단을 저장해 재방문 시 점수 변화를 델타로 비교합니다.

  • 마크다운 복사 / .md · .html · .docx 다운로드
  • 같은 URL 재진단 시 이전 대비 ± 점수 표시
  • 한국어 · 영어 인터페이스 자동(브라우저 언어 기준)
🤖

다중 LLM 제공자 (BYOK)

Anthropic(Claude) · OpenAI(GPT) · Google(Gemini) 중 원하는 제공자를 골라 본인 키로 정밀 진단을 실행합니다.

  • 설정에서 제공자 드롭다운 + 단일 키/모델
  • LLM 호출 1회로 정성 채점 + 재작성 동시 처리
  • 키·모델은 설정에서 언제든 변경

하이브리드(휴리스틱 + AI) · 타깃: 야근할 때 집중 잘 되는 커피

인용할 이유 / 안 될 이유

✅ 사실 밀도·통계 (4/5) — "카페인 함량 12mg/100ml, 산미 3.5"
✅ 렌더링(SSR) (5/5) — 본문이 서버에서 렌더되어 크롤러가 읽기 쉬움
✅ 최신성 신호 (4/5) — dateModified 2026-05
❌ 구조화 데이터(JSON-LD) (0/5) — Product/Article 스키마 없음
❌ 답변 우선 구조 (2/5) — 첫 200단어가 브랜드 스토리로 시작
❌ llms.txt (0/5) — 없음

스코어카드

B1 AI 크롤러 접근성 ·354/5
B3 구조화 데이터 ·200/5
A1 답변 우선 구조 ·152/5
A2 사실 밀도·통계 ·154/5
A5 추출 가능성·청크화 ·143/5

… 외 A3·A4·A6~A10 · B2·B4·B5 (총 15항목)

항목별 진단

A1 답변 우선 구조2/5
왜: 첫 200단어가 주 질문에 직답해야 인용된다.
근거: "1998년, 작은 로스터리에서 시작한 우리의 이야기는…"
B3 구조화 데이터(JSON-LD)0/5
왜: 구조화 데이터가 개체·맥락을 기계에 전달한다.
근거: JSON-LD 구조화 데이터 없음 (DOM 직독 확인)
A2 사실 밀도·통계4/5
왜: 통계·사실 밀도가 가장 큰 레버.
근거: 카페인 12mg/100ml · 산미 3.5 · 250g

CEP 진단 — 상황 진입점

미대응 2 부분 1 충분 1

미대응 야근 중 집중력을 유지하려 할 때
언제: 야근왜: 집중기준: 카페인·간편함
예상 질문: 밤샘 작업할 때 집중 잘 되는 커피 추천해줘
부족한 점: 제품 스펙만 있고 '야근/집중' 상황 언어가 없음
Before 고농도 아라비카 원두를 사용합니다.
After 야근처럼 집중이 필요한 순간을 위해 100ml당 카페인 [수치 삽입]mg을 담았습니다.
필요 근거: 카페인 함량 수치 + 성분표/시험성적서 출처
부분 손님과 편하게 대화할 커피가 필요할 때
누구: 손님경험: 부담 없는 대화
예상 질문: 집들이 때 손님 대접용으로 무난한 원두 뭐가 좋아?
부족한 점: 맛 프로필은 있으나 '대접·부담 없음' 맥락 부재
Before 균형 잡힌 바디감의 미디엄 로스트.
After 취향을 안 타는 미디엄 로스트라, 손님 대접처럼 실패하면 안 되는 자리에 무난합니다.
필요 근거: 로스팅 레벨 · 대중 선호 근거(리뷰·평점)

CEP의 필요 근거는 A2(통계)·A3(출처) 점수를 올리는 실제 방법입니다.

사용 방법

세 번의 클릭

1

페이지 열고 아이콘 클릭

진단할 페이지에서 GeoScore 아이콘을 누르면 사이드 패널이 열립니다.

2

타깃 쿼리 입력 (선택)

"어떤 질문의 답으로 인용되길 원하나요?" 비워두면 자동으로 추론합니다.

3

진단 실행

점수·스코어카드·CEP·처방이 담긴 리포트가 나옵니다. 정성 항목은 설정에서 API 키 입력 시 채워집니다.

프라이버시

본문은 당신이 고른 곳에만 갑니다

  • 자체 서버가 없습니다. 백엔드·DB·계정·애널리틱스·텔레메트리 없음.
  • 페이지 본문은 사용자가 선택한 LLM 제공자(택1)에게 본인 API 키로만, 진단 실행 시에만 전송됩니다.
  • API 키와 진단 기록은 브라우저 로컬(chrome.storage.local)에만 저장됩니다.
  • 선택한 제공자 외 제3자에게 데이터를 판매·공유하지 않습니다.
🔒

허용 네트워크 대상은 딱 필요한 곳만

진단 대상 도메인(robots.txt·llms.txt·raw HTML)과, 사용자가 고른 LLM 제공자 1곳:

  • api.anthropic.com
  • api.openai.com
  • generativelanguage.googleapis.com
